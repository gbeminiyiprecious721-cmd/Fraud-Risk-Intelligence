Methods, stability and investigation guidance

MDI sums fitted impurity importance across a raw input's numeric, missingness and one-hot columns. It is biased by cardinality and correlation; it is not permutation sensitivity. TreeSHAP first sums signed components per raw input, then averages absolute grouped contributions across 512 label-free validation examples. These are different statistics, not interchangeable evidence of causal importance.

Local baseline uses the trees' recorded weighted training paths. Positive/negative contributions increase/decrease this model score relative to that baseline. Other features retains every omitted contribution. Additivity is a numerical identity, not proof that a feature causes fraud. Synthetic numeric defaults and unknown categories can be unrepresentative.

Use these associations to guide investigation of data quality and case context; do not automate declines or promote experimental challengers. Reference assumptions, correlated inputs, anonymised features and reused validation limit interpretation.

Methodology, investigation guidance and limitations

Reference V1 is the earliest validation third; later V2/V3 are disjoint chronological windows. All scores are out-of-sample for the frozen Random Forest, but validation was reused during development. Relative seconds are not calendar dates.

Numeric: reference-only quantile bins, PSI with additive 0.0001 smoothing, KS empirical distance. Categorical: base2 Jensen–Shannon divergence. Demonstration investigation rules: PSI ≥0.20 or KS ≥0.10; JS ≥0.05. Minimum sample 200; no IID p-values or significance claims. Missingness increase ≥5 percentage points and invalid values warrant quality investigation. Inspect upstream changes before considering any model response; never retrain automatically.

Score-tail criterion is strictly greater than fixed reference q95, not a calibrated fraud probability. Histogram bins have open-ended extremes; ties may reduce the number of quantile bins. Missing/nonfinite numeric values are tracked separately.

    Responsible Use & Limitations

    • This score is an investigation-prioritization signal only — it ranks transactions relative to one another, for a human investigator to triage.
    • It must never be used to automatically decline, block, or flag a transaction as fraud without human review.
    • It is not a calibrated probability — no reliability diagram, Brier score, or recalibration has been performed anywhere in this project.
    • Every queue record shown here is synthetic and portfolio-safe, fabricated for this demo and scored on request — none are real or training transactions.
    • The historical Stage 10 metrics (Model Insights) are a separate, fixed, one-time measurement on held-out data — they describe the model in general, not any specific prediction shown on this page, and must never be read as if they applied to an individual transaction.
    • This project makes no demographic fairness claim; a Responsible AI assessment was performed on the model (Stage 12) but is not re-run or re-validated by this dashboard.
    • This is a portfolio demonstration, not production banking software, and was never evaluated, reviewed, or approved as one.
