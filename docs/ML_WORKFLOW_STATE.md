## Current Stage
**Stage 7 — Model Selection**: implementation was **authorised and began** (`src/model_selection.py`, `scripts/run_stage7_model_selection.py`, `tests/test_model_selection.py`). A no-skill baseline and a small 3-feature Logistic Regression baseline completed validly (`docs/_stage7_baselines_raw.json`). The full-feature Logistic Regression experiment (813-column Stage 5 output) was **interrupted**; diagnosed to severe missingness-indicator multicollinearity interacting with `liblinear`. This repository now has version control (commit `c03622b`). A bounded chronological pilot (15,000 earliest `train` rows, corrected collapsed-indicator preprocessing, `solver="saga"`) made the fit fast and tractable (13.7s, vs. a multi-hour `liblinear` hang) but **did not reach convergence within 1000 iterations in either `class_weight` configuration tested** — the solver switch helped, it did not solve the problem outright, exactly as cautioned against assuming. A follow-up convergence investigation on the SAME subset found 157 column pairs (64-66 distinct columns) with |correlation| > 0.99 among the underlying numeric VALUE columns (the indicator collapse only deduplicated missingness MASKS, never touched this), and an initial, since-CORRECTED finding that `class_weight="balanced"` made SAGA's loss oscillate -- re-measured under the optimizer's actual weighted objective, that claim was substantially weakened (both weightings behave similarly). `SGDClassifier(loss="log_loss")` converges by its own criterion in under a second but reaches a markedly worse solution (one config's validation AP ≈ the no-skill floor). A controlled A/B numeric-redundancy-reduction experiment (same subset, same solver/seed, `class_weight=None` in both arms) found dropping 48 redundant columns changed almost nothing (fit time, loss trajectory, and diagnostic AP all nearly identical between arms) -- a genuine negative result. **A final, definitive check raised `max_iter` to 3000 (3x) on the unchanged 542-feature Arm A representation: still did not converge** (hit the cap, `ConvergenceWarning` still raised, fit time 41.7s) — ruling out "just needs a few more iterations" as a practical fix at this subset size. Numeric-feature reduction (542->494) is NOT adopted into the reference pipeline, per explicit instruction — kept only as documented negative evidence. **Stage 7 is not complete and remains under controlled review** — no further modelling (Random Forest, Gradient Boosting, further ablations, hyperparameter search, or any scale-up past this pilot's 15,000 rows) resumes without explicit approval. No model has been trained to completion on the full feature set. `final_test` has not been accessed.

- 2026-10-24 — Proposed PR-AUC (research metric), precision/recall@fixed-capacity (operational metric), and cost-sensitive threshold selection (decision layer) as the evaluation approach, ruling out plain accuracy — why: standard reasoning for severe class-imbalance problems (ROC-AUC can look deceptively high under imbalance; accuracy is structurally uninformative), independent of this dataset's actual (not yet measured) class balance. Alternatives considered: ROC-AUC alone (rejected, imbalance-sensitive), a fixed 0.5 threshold (rejected, not cost-optimal by construction). Validated by: methodological reasoning only — **no model exists yet, so no metric value has been computed**.
